## Halcon_UI 前后端通信协议总结

### 一、传输层

基于 **WebSocket（RFC 6455）** 协议，使用**二进制消息（Binary Frame）**承载应用层数据。

- **WS 端点**：`ws://<host>:<port>/ws`
- **HTTP 端点**：`GET /` 及 `GET /<path>` 提供静态文件服务（前端页面）
- 服务端主动推送、客户端也可主动发送，全双工双向通信
- 服务端发送为**广播**（所有已连接客户端），接收为**汇聚**（任一客户端发来的消息）

---

### 二、应用层帧格式

每一条应用层消息封装为一个**固定帧头的二进制包**，结构如下：

```
┌─────────────────┬─────────────────┬─────────────────┬──────────────────┬──────────────────┐
│  magic (4B)     │  json_len (4B)  │  data_len (4B)  │  JSON 正文       │  二进制数据       │
│  0xDEADBEEF     │                 │                 │  (UTF-8, 无 \0)  │  (可选，可为空)   │
└─────────────────┴─────────────────┴─────────────────┴──────────────────┴──────────────────┘
```

**规则**：
- 所有多字节整数字段均为**大端序（Big-Endian / Network Byte Order）**
- `magic`：固定魔数 `0xDEADBEEF`，用于帧同步校验
- `json_len`：JSON 正文的 **UTF-8 字节数**（不含 C 字符串末尾的 `\0`，但实际上传输时 JSON 字符串后可能跟一个 `\0`）
- `data_len`：后续二进制数据的字节数，**可为 0**（表示纯 JSON 消息，无二进制负载）
- 帧总长度 = **12 + json_len + data_len** 字节
- 单条消息最大 **64 MB**（`WS_MAX_MESSAGE_SIZE`）

---

### 三、JSON 协议格式

JSON 正文是一个对象，**必须**包含两个顶层字段：

```json
{
  "CMD": <整数>,
  "Data": { ... }
}
```

**规则**：
- `CMD`：命令标识，必须为**整数**（范围 0~999）
- `Data`：必须是一个 **JSON 对象（dict）**，内部字段由具体 CMD 决定
- 服务端收到消息后会对 JSON 做**协议校验**：缺少 `CMD`、缺少 `Data`、`CMD` 非整数、`CMD=0` 时缺少必要字段等情况均返回错误码

---

### 四、CMD=0 —— 图像帧（特殊说明）

`CMD=0` 是唯一**同时携带 JSON 和二进制数据**的消息类型，用于传输图像。

**JSON `Data` 必须字段**：

| 字段 | 含义 | 类型 |
|------|------|------|
| `宽` | 图像宽度（像素） | 整数 |
| `高` | 图像高度（像素） | 整数 |
| `图号` | 图像窗口编号（多窗口路由） | 整数 |
| `通道` | 通道数：`1` = 灰度，`3` = RGB | 整数 |
| `fmt` | 编码格式标记（服务端发送时自动填入 `"jpeg"`） | 字符串 |

**二进制部分**：JPEG 压缩后的图像数据。

**工作流程**：
1. **服务端发送**：Halcon 侧持有 `HObject` 图像对象，调用 `WSendWebData` 时自动通过 **libjpeg-turbo**（质量 80）将原始像素压缩为 JPEG，填入二进制段
2. **客户端接收**：解析帧头 → 读取 JSON 获取宽/高/图号/通道/fmt → 若 `fmt=="jpeg"` 则将二进制段作为 JPEG 解码渲染；若没有 `fmt` 字段则按原始 planar 像素（R 平面 + G 平面 + B 平面）直接渲染

**客户端接收**：同样走同一帧格式，但二进制部分是**未压缩的原始像素**（灰度：W×H 字节；RGB：3×W×H 字节，布局为 R平面 + G平面 + B平面）

---

### 五、通信模式

| 方向 | 说明 |
|------|------|
| 服务端 → 客户端 | **广播推送**：`SendWebData` 将消息发给所有已连接客户端 |
| 客户端 → 服务端 | **汇聚接收**：`RecvWebData` 从任意客户端收取一条消息，支持超时（<0 永久阻塞、=0 非阻塞、>0 等待毫秒） |

收发队列为**有界 FIFO**（深度 8），满载时**丢弃最旧消息**。

---

### 六、连接管理

- WebSocket 协议级 **Ping/Pong 保活**：每 20s 发一次 ping，60s 无 pong 则断开
- 最大同时连接客户端数：**8**
- 客户端断开时自动清理，服务端对端发送 close 帧确认
